# 春风 · 遇事不决，可问春风（可运行版）

需求文档《个人决策沙盘AgentTeam设计方案与提示词.docx》的可执行实现。五个 Agent、六阶段流转、指令路由、看板版本递增、跨立场口径同步全部落地；另加一道入口接待（判断是不是真在做决策）和一层可选的外部情报（元宝搜索），两者都不占圆桌席位。纯文本看板，不依赖前端；不联网也能完整跑通。

程序只用 Python 标准库，装好 Python 3.8+ 就能跑，不需要 pip install。

---

## 一、六阶段链路

| 阶段 | 谁在工作 | 代码里的位置 |
|---|---|---|
| 1 入口 | 入口接待判定是不是决策 → 只唤起 A1，其余四个待命 | `core/intent.py`、`Sandbox._run` |
| 2 探询+取证 | A1 一次只问一题，逐题深挖追问到背景澄清，不设题数上限；档案确认后由 A1 提出最多 2 条检索请求，编排层统一执行并按地域/品类/预算/政策/时间窗口取证；A2/A3 交叉质询初稿各提 1 条证据请求，合并去重后共享同一证据池（可选，失败降级） | `Sandbox._probe`、`Sandbox._seed_research`、`Sandbox._cross_examine`、`core/research.py`、`core/search.py` |
| 3 并行+互质 | A2/A3/A4 先同时独立研判，各自只拿档案副本；随后 A2/A3 做 1 轮基础交叉点评（只回应、不新增论据）；出现“风险被接受但未降级”或“论据被反驳但未修订”等未回应冲突时，再追加 1 轮定向回应，最多 2 轮 | `Sandbox._judge_parallel`、`Sandbox._cross_examine`、`Sandbox._find_conflicts`（ThreadPoolExecutor 并发） |
| 4 看板 | A5 汇总三方，生成《沙盘看板》V1，列出 A–E 交互项 | `Sandbox._refresh_board` |
| 5 交互 | 用户质疑 / 改参数 / 补背景，硬编码路由定向分发，版本号递增 | `Sandbox._interact` 及各 `_handle_*` |
| 6 收尾 | 用户说结束，A5 输出最终报告，末尾 `_SESSION=CLOSED` | `Sandbox._final` |

三个流转标记是编排层的唯一判据，不解析正文：`_BACKGROUND_READY=true`、`_SIDE=PRO/CON/NEU`、`_SESSION=CLOSED`。

## 二、快速开始

```powershell
cd "D:\file\Project.zhouying\个人决策沙盘 Agent Team"

# 1. 自检：提示词、金额解析、量化算术、路由规则
python run.py --check

# 2. 不配 Key 也能跑：预置剧本全链路演示（20 万级家用车）
python run.py --demo

# 3. 交互模式：自己输入决策问题，自己发指令
python run.py

# 4. 网页对话界面（推荐）：浏览器里聊，不用盯终端
python run_web.py

# 5. 单元测试：663 个用例，覆盖路由、入口判定、外部情报、中文金额、模型契约、模型调用、配置装配、落盘、续跑、导出、复查与 Web 防护
python -m unittest discover -s tests -t tests
```

`python run_web.py` 会启动本地服务并自动打开 `http://127.0.0.1:8765/`，也可以直接双击 `启动网页.bat`。
换端口用 `--port 8766`，不想自动开浏览器加 `--no-browser`。网页用的是同一套 `Sandbox`，
记录照样落在 `runs/`，两种入口可以混用。推演进行中随时可以停止：网页点顶栏「停止推演」；CLI 在交互阶段输入「停止推演」，任何阶段按 `Ctrl+C`。停止不会调用 A5、不生成最终报告，已产出的档案与看板版本照常落盘。

现场不想等停顿，加 `--fast`：`python run.py --demo --fast`。`--demo` 固定走预置剧本、不调模型；想用真实模型跑同一套预置答案，加 `--provider llm`。

想在真实模型下跑一遍 Web 端到端（自动应答、注入质疑/改参数/收尾）：
`python tests/manual_web_e2e.py --mode live`。它以 `manual_` 开头，不进 unittest discover。

### 接真实大模型

首次使用先复制模板（`config.json` 已在 `.gitignore` 中，不会被提交）：

```powershell
copy config.example.json config.json
```

然后编辑 `config.json`：

```json
{
  "provider": "auto",
  "base_url": "https://ark.cn-beijing.volces.com/api/v3",
  "api_key": "",
  "model": "doubao-seed-1-6-250615"
}
```

- 推荐把 Key 放在环境变量 `SANDBOX_API_KEY` 里，`api_key` 留空；只有本机临时调试才写入 `config.json`。该文件已在 `.gitignore` 中，不要提交、不要截图分享。

- `base_url` 必须是 OpenAI 兼容接口（火山方舟、DeepSeek、通义、自建 vLLM 都可以），程序请求 `<base_url>/chat/completions`。
- `api_key` 留空时也可以走环境变量：`$env:SANDBOX_API_KEY="你的 Key"`。
- `provider: "auto"` 表示「有 Key 走模型，没 Key 走预置剧本」；写 `"llm"` 强制模型，写 `"mock"` 强制预置剧本。
- `temperature` 已按文档配置说明设好：A1 0.3、A2 0.5、A3 0.5、A4 0.2、A5 0.4。
- `quant` 段可调量化口径，全部可省略（省略即用内置默认值）：`emergency_months` 应急金月数（默认 6）、`sensitivity_pct` 敏感性浮动比例（默认 0.2）、`opportunity_low` / `opportunity_high` 机会成本年化区间（默认 0.03 / 0.05）。改完跑 `python run.py --check` 会按新口径重算。
- 外部情报是可选的，支持两种凭据，填任意一种即可：
  - **SecretId + SecretKey**（腾讯云标准方式）：填 `search.secret_id` / `search.secret_key`，程序用 TC3-HMAC-SHA256 签名调用 `https://wsa.tencentcloudapi.com`（Action `SearchPro`，Version `2025-05-08`）。也可用环境变量 `TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`。
  - **服务 API KEY**（`sk-` 开头）：填 `search.api_key`，走 Bearer 认证调用 `https://api.wsa.cloud.tencent.com/SearchPro`。也可用环境变量 `TENCENTCLOUD_WSA_APIKEY`。
- 两种方式都把带链接与发布日期的结果并入《决策背景档案》；`search.endpoint` 留空时会按凭据自动选择域名。
- 检索词由 Agent 提出：A1 在档案阶段、A2/A3 在交叉质询初稿、A4 在关键参数缺失时输出检索请求，编排层统一去重、限次、编号并共享证据池；没有请求时回退到档案短查询。入选条目并发抓正文，抽取金额/利率/补贴/日期；抓取失败只标「未抓取：原因」。
- 预算写死在 `core/research.py`：每场最多 6 条请求、10 条正文，A1 最多 2 条、A2/A3/A4 各 1 条，每条请求最多取 3 条。`search.fetch_pages`（默认 true）控制正文抓取，`fetch_timeout`（默认 6 秒）、`fetch_chars`（默认 1200 字）限制成本；`refresh_hours`（默认 6 小时）决定 `auto` 模式多久后按同一主题重新联网。
- 看板会列出每个请求的发起方、查询与命中数，并显示每条情报被谁引用、哪些未引用；只贴 `[外N]` 而正文没有命中条目数字/实体的，标记为「弱引用」。
- 没填凭据、接口超时或被限流，链路照常继续：档案、逐轮记录与看板都会显式写「外部情报：未获取 ｜ 原因」，不会静默省略；`search.mode` 可设 `auto`（默认）/ `live` / `cache` / `off`，现场断网演示建议用 `cache`。

> 预置剧本模式不会调用任何模型，所有论据与风险由本地模板生成，量化部分是**真实算术**（改参数会真的重算）。它的用途是彩排、录屏、断网兜底，不适合当作真实研判结果对外展示。

### 日常使用的几个入口

- 右上角「运行模式」在开新一场前切换：自动 / 真实模型 / 预置剧本。选「真实模型」但没配 Key 时会直接报错，不会静默降级。
- 右上角「历史」列出 `runs/` 下最近 20 场，点开可只读回看最终报告、任意看板版本（V1…Vn）或全轮次记录；有状态快照的场次还能点「继续这场推演」，从当前版本接着质疑、改参数、补背景，版本号继续递增，`transcript.md` 追加而不覆盖。回看不会改动当前会话。打开场次时，若该场有外部情报，会先显示独立的「外部情报」面板：来源与抓取时间、每条要点、正文抓取状态，以及被谁引用或标记为弱引用。
- 看板与报告的卡片头有「下载」，可直接存成 `.txt`；历史记录同样能下载。历史里还可「导出 JSON」，一次拿到档案、每版看板、最终报告、外部情报与漂移记录。
- 已经有《决策背景档案》时，可在欢迎页点「粘贴已有档案（跳过 A1）」直接进入并行研判；CLI 用 `python run.py --paste sample_archive.json`。
- 真实模型结束后会显示「模型调用 N 次 ｜ 累计 X 秒」，方便判断耗时与成本来自哪里。
- 每场收尾都会生成 `复查清单.json`（30 天后到期，含切换条件与兜底建议）；打开页面时若有用例到期，会提示「有 N 场决策到了复查时间」，可在「历史 → 复查清单」查看并「标记已复查」。
- 输入上限：问题 500 字、单次回答 2000 字、请求体 256 KB。超出会明确报错，不会悄悄截断。
- 真实模型一场推演约 1–3 分钟（取决于模型与网络；A1 逐题深挖追问到背景澄清，V1 看板本身可能要等约一分钟）。等待时输入框会锁定并显示已用时，出现新问题或看板后自动解锁。
- 真实模型输出缺少必需字段时，会自动补一次修正请求；仍不合契约就中止本场并保留已有记录，不会带着半成品继续生成看板。

## 三、指令怎么打

看板第六段列了 A–F 六项，直接说人话即可，路由是规则判定，不靠模型猜：

| 你说的话 | 判定 | 发生什么 |
|---|---|---|
| `反方说的养车成本每年两万太高了，我实际一年一万二` | B 质疑反方 → A3 | A3 重算并下调风险等级；若改动成本口径，A4 同步重算并把新口径写回档案（后续补充背景沿用，不回退默认值）；摘要抄送正方一次 |
| `我质疑正方第一条论据，搬家后通勤距离缩短，效率提升没那么大` | A 质疑正方 → A2 | A2 正面回应并修订论据，摘要抄送反方一次 |
| `我把可动用存款改成150万` | C 修改参数 → A4 | 仅 A4 重算，两方结论保持不变；改「养车」则新口径同样写回档案 |
| `补充一个情况：公司明年搬到南山，通勤距离缩短一半` | D 补充背景 → 全组 | 先更新档案，再三方全量重算；已修订的成本口径与已改参数保持不变，量化若有变化会写入漂移日志 |
| `结束沙盘，给我结论` | E 收尾 → A5 | 输出最终报告，`_SESSION=CLOSED` |
| `停止推演` / `不继续了` | F 停止 | 不再推进后续阶段，不调用 A5、不生成最终报告；已产出的档案与看板版本保留在 `runs/`，状态记「已停止」 |
| 说不清的指令 | 无法归类 | 回问一次并列出 A–F，同轮不连续追问 |
| `把月收入改成-100` / 改成 9.99 亿 | C 参数，但值非法 | 按非法参数回问，不写档案、不生成新看板 |
| `结束之前先把存款改成150万` | C 参数（条件从句不算收尾） | 只重算量化，不生成最终报告 |
| `还没结束，补充一个情况` / `别结束` | D 补充背景 / 无法归类 | 否定或条件从句里的“结束”不触发 CLOSE |
| `不要继续用打车方案了` | 无法归类（不是 F 停止） | 否定从句里的“继续”不当作停止指令，回问一次 |
| `我把存款改到150万，但风险还是太高` | C 参数（同句含质疑也按改参数优先） | 存款照改，质疑不会吞掉参数 |
| `年养车成本改成20万` | C 参数，年额折算 | 按 16,667 元/月写入档案，不再当成 20 万/月 |
| `首付30%，总价200万` | C 参数，百分比不算金额 | 一次性支出上限取总价 200 万，30% 不进数字 |

金额支持中文写法：`一百五十万`、`一万二`、`1.15万`、`3000` 都能解析。

## 五、相对需求文档，落地了哪些优化

| 优化项 | 落地方式 |
|---|---|
| A1 演示路径砍到 2–3 问 | `--demo` 只走一批 3 问并预置答案；真实交互逐题深挖追问到背景澄清，不设题数上限，连续重复同一题才提前归档 |
| 沙盘内路由硬编码在编排层 | `core/router.py` 纯规则判定，按 STOP > CLOSE > CHALLENGE > PARAM > NEW_FACT > UNKNOWN 顺序；它判的是「沙盘里这条指令属于哪一类」，错了会改错参数，所以永不交给模型 |
| 入口接待用软门禁 | `core/intent.py` 先跑规则；规则拿不准才让模型判一次，判不出、返回异常或调用失败一律放行——漏判（把真决策挡在门外）比误判（多跑一场）代价大 |
| 外部情报由 Agent 提请求、编排层统一取证 | A1 建档后、A2/A3 交叉质询初稿、A4 关键参数缺失时，各自动生成 `research_requests` / `evidence_requests`；编排层去重、限次（每场 6 条请求 / 10 条正文，A1 2 条、A2/A3/A4 各 1 条）、统一编号进同一证据池。A2/A3 第二阶段只更新 cross 的 point/basis，不增删条目；A4 的 `external_use.cited` 必须能在条目要点里核到；A5 判定理由在正反方已引用时必须带真实 `[外N]` |
| 交叉质询按需追加第 2 轮 | `Sandbox._find_conflicts` 只认两类保守冲突：A2 接受反方风险但 A3 未降级；A3 反驳正方论据但 A2 未修订。命中才让被点名一方做一次定向回应，不新增论据、不检索；看板显示「第 1 轮 → 第 2 轮 → 收敛/未收敛」 |
| 五个 Agent 强制 JSON / 固定字段 | 每份提示词末尾都写了输出契约；`core/jsonx.py` 容错解析，失败自动补一次修正请求；解析不了就中止，不带病生成看板 |
| A5 增加观点漂移日志 | 每次修订记「哪一方、哪一项、原值→新值、依据」；补充背景引起的量化变化同样记一条；看板末尾留痕，最多显示近 6 条 |
| 修订摘要抄送另一方一次 | `Sandbox._sync`：摘要截断到 50 字，抄送一次，对手方只回一句「口径已对齐」或「同步调整第 X 条」，同轮不反复触发 |
| 演示看板精简为四行 | 看板顶部固定「速览四行」：问题、正方、反方、量化；下面仍保留文档规定的七段明细，投屏与复盘两不误 |
| 成本口径修订触发 A4 同步重算 | 对应演示脚本第 5 步：A3 下调后，A4 以新的月度增量重算，漂移日志同时记一条量化变更；新口径写回档案，后续补充背景沿用，不再回退默认 1,650 元/月 |
| 规则路由可单测 | `tests/test_router.py` 覆盖五类指令与参数抽取，改关键词后跑一遍测试即可回归 |
| 参数口径防串味 | 改「月收入」时不会把前面的数字误记成存款；「养车每年 1.5 万」会先折算成 1250 元/月再进看板；负数与超上限按非法参数回问，非数字归入无法归类，三者都不落档案 |
| 否定/条件从句不误触发 | 「别结束」「还没结束」「结束之前先改参数」不会生成最终报告；「不要继续用打车方案」不会终止整场；明确改参数与质疑同句出现时参数优先，质疑不吞数字 |
| 年/月口径与百分比防误判 | 「年养车成本 20 万」「每年的养车费用 2 万」按年折算，「明年开始每月租金 5000」按月不折算；「首付 30%」不当成 30 元，一次性支出上限优先取总价/预算 |
| 量化口径可配置 | `config.quant` 可调应急金月数、敏感性浮动比例与机会成本年化区间；月消耗为 0 时显示「不适用」而非 0 个月；财务四项缺失两项及以上时看板标注「按假设值估算」，参数变更后二、三段标注「数字为参数变更前口径」 |
| 场次续跑与版本回看 | 历史抽屉可打开任意看板版本与最终报告；有 `状态快照.json` 的场次可「继续这场推演」，复用同一 `runs/` 目录、版本号继续递增、transcript 追加不覆盖；`read_run` 支持 `kind=board&version=N` |
| 结构化导出、粘档案与成本可见 | 历史可导出 JSON（档案 / 每版看板 / 最终报告 / 外部情报 / 漂移）；Web 欢迎页可粘贴已有档案跳过 A1，`run_paste` 与 CLI `--paste` 共用；真实模型结束后显示调用次数与累计耗时 |
| 决策复查闭环 | 收尾自动把 `report.switch` 与 `report.fallback` 转成 `复查清单.json`（30 天后到期）；Web 首页提示到期场次，历史里可查看清单并「标记已复查」；`/api/reviews` 支持批量读取 |
| 检索与上下文工程 | A1/A2/A3 提检索请求，`core/search.search_queries` 执行短查询、并发抓正文并抽结构化要点；`core/research` 负责去重、预算与证据池编号；交互阶段命中价格/政策/利率等词才重检，60 秒节流；缓存按主题短查询 + `refresh_hours`；A1 问答历史按 12000 字窗口保留 |

## 六、现场怎么用（按 90 分钟排期）

1. **0–10 分钟**：`python run.py --check` 确认逐项 OK（提示词、金额、参数抽取、算术、路由、模型与情报配置）；`python run.py --demo --fast` 空跑一遍，确认没有报错。
2. **10–40 分钟**：如果要用真实模型，把 Key 填进 `config.json`，用 `python run.py` 走一遍真实链路；模型输出不符合 JSON 契约时，先看 `runs/<时间>/transcript.md` 里是哪一步解析失败。
3. **40–78 分钟**：直接走七步决策链路，中间留出质疑与改参数的互动。
4. **78 分钟以后**：录屏、截图。`runs/` 目录里已经有完整的 transcript 与每版看板，可直接截。

演示案例与文档一致：**要不要买一台二十万级的家用车**。

## 七、降级预案

| 情况 | 动作 |
|---|---|
| 模型 Key 不可用 / 现场断网 | 直接 `python run.py --demo`，预置剧本仍能完整演示六阶段 |
| 探询环节太慢或追问跑偏 | `--demo` 已固定 3 问；真实模式逐题深挖追问，直到背景澄清或用户拒绝补充才出档案，连续重复同一题会提前归档；也可输入「结束」收尾 |
| A1 想跳过 | `python run.py --paste sample_archive.json`，直接进入并行研判 |
| 并行编排不稳 | 本程序用线程做真并发；若模型侧限流，把 `config.json` 的 `timeout` 调大，或在 `core/orchestrator.py` 把三路 submit 改成串行（不推荐，会失去并行看点） |
| 口径同步导致链条变长 | 同步规则写死在 `_sync` 里，同轮只触发一次；需要临时关闭就把 `_sync` 里的两行注释掉，看板日志会缺一条记录 |

## 八、为什么不是单 Agent 写五个 prompt

- **隔离**：并行三路各拿档案副本，A2 看不到 A3 的结论，立场不会互相污染；单 Agent 在同一个上下文里连着写三段，后写的必然被前写的锚定。
- **可复核**：A4 的算式与代入数字单独成段，A5 不许篡改，任何一条结论都能倒推回原始数字。
- **可介入**：用户质疑只定向打到一方，另一方的结论与数字保持不变，改参数只重算量化，三种介入各有明确边界；单 Agent 做不到这种「只改一处」的粒度。
- **口径一致**：一方修订后摘要抄送另一方一次，避免两方基于不同数字继续对话；这是多智能体特有的问题，也是这套方案主动解决的点。
- **可验证**：每个阶段都有标记位与结构化输出，链路是否跑通由标记判定，不由模型自述。
- **情报不是第七个 Agent**：检索由代码完成，产出带 `url` 与 `date` 的情报包写进档案；A2/A3 只能按 `[外N]` 编号引用，且正文要写出条目里的具体数字或实体，不得编造来源；看板会统计 `[外N]` 被哪条论据/风险引用、哪些未引用、哪些只是弱引用，并要求 A2/A3 写明未使用原因。A4 只能引用能在条目要点里核到的数字，A5 在正反方已引用时判定理由必须带真实 `[外N]`。圆桌上仍然只有五个人，情报是 A1 的工具，不是第六个立场。

## 九、已知边界

- 编排层与看板渲染仍是纯文本，`web/` 只负责把文本流分发到浏览器，没有引入前端框架，也没有把状态机搬进浏览器。
- Web 服务只监听本机 `127.0.0.1`，没有登录与鉴权，不要绑定到公网地址。
- 看板与最终报告必须给出明确判定：「执行主方案 / 暂缓 / 放弃主方案」三选一，并附判定理由与失效条件；A5 不得只汇总三方观点，也不得写「视情况而定」这类无结论表述。收尾报告与最近一版看板判定不一致时，代码会锁定看板判定并写明「不静默改判」。
- A1 的问题由模型生成，真实模式下措辞会有波动；演示模式用的是固定三问。
- 预置剧本模式的论据是模板化的，只用于跑通链路，不代表真实研判质量。
- 跨立场同步只处理「论据修订」与「风险等级调整」两类修订表述；其他类型的改动按参数变更或补充背景处理。
- 外部情报依赖腾讯云元宝搜索的可用性与账户余额：未配置 Key、接口超时、限流，或返回条目缺链接/日期，都会整层跳过并写明原因，不会伪造一条“真实世界数据”。正文抓取也可能被站点拒绝或超时，只会标「未抓取：原因」并保留标题/摘要，不影响其它条目；弱引用只做提示不删除，避免误伤合理引用。每场检索预算固定 6 条请求 / 10 条正文；模型提的请求过多时会被截断并记入看板，不会无限追搜。A2/A3 的请求由编排层合并共享，但模型仍可能只提对自己有利的证据；看板会显示发起方与未引用原因，便于人工复核。搜索质量取决于 query 与结果源：档案越具体（城市、总价、月供、时间窗口），命中越可用。
- 交叉质询默认 1 轮基础点评，只有命中两类保守冲突才追加 1 轮定向回应，最多 2 轮；第 2 轮不发起检索请求，避免预算被辩论吃光。收敛只表示双方回应为接受/限定，不代表事实一定一致；未收敛会写进看板并作为 A5 的失效条件。
- 参数有值域上限：月收入 / 月结余 1,000 万，可动用存款 / 一次性支出上限 10 亿，月度增量支出 100 万；负数与超上限按非法参数回问，非数字被归入无法归类、回问一次；三者都不写档案、不生成新看板。
- 财务四项缺失时，看板与档案的财务行会标「未提供（按假设值 X）」，A4 仍用默认值算出月数；缺失两项及以上时，看板会额外标注「按假设值估算，仅作方向参考」，最终报告的权威口径也会附带缺口警告。这类数字不代表真实输入。
- 月消耗为 0（月收入等于月结余且月度增量支出为 0）时，看板显示「可支撑月数不适用」，不会写成 0 个月；`authority` 的 `months` 为 `None`，收尾报告不再做月数纠偏。
- 参数变更只重算 A4，A2/A3 正文仍引用变更前数字，因此看板二、三段会标注「数字为参数变更前口径」，避免把旧数字误读成本轮结论。
- A1 探询阶段用户回答「停止推演」会立即取消本场，不生成档案、不调用 A5；与交互阶段的 STOP 路由共用同一套判定。
- 中文金额解析会跳过「30%」「三成」这类比例，不把百分比当成元；「首付」「预算」「总价」同时出现时，一次性支出上限优先取预算/总价。
- Web 服务校验 Host 与 Origin，只接受本机来源；即使误绑到 `0.0.0.0`，外部页面也无法直接调用这些接口。
- 用户原文写入记录前会压成单行并截断（行级 500 字、块级 8000 字），防止伪造记录结构或把 `transcript.md` 撑爆。
